1. Problem Statement١. المشكلة

In many communities, reporting infrastructure problems and public safety concerns is slow and disorganized:
  • Citizens do not know where to report community problems.
  • Administrators receive reports through different, disconnected channels.
  • Duplicate reports about the same problem create unnecessary work.
  • Choosing the right response team for each incident is difficult.
  • Citizens cannot see whether their reports are being handled.
  • Administrators lack centralized analytics and reporting tools.
في كثير من المناطق، الإبلاغ عن مشاكل البنية التحتية والسلامة العامة بطيء وغير منظم:
  • الناس ما يعرفون وين يبلّغون عن مشاكل الحي.
  • البلاغات توصل للمسؤولين من أماكن مختلفة ومتفرقة.
  • تتكرر البلاغات عن نفس المشكلة، وهذا شغل زايد.
  • صعب اختيار الفريق المناسب لكل مشكلة.
  • المواطن ما يعرف إذا بلاغه قاعد يتعالج أو لا.
  • المسؤولين ما عندهم مكان واحد فيه إحصائيات وتقارير.

2. Proposed Solution٢. الحل المقترح

ResQ is one centralized platform where citizens report incidents with a description, photos and a map location. An AI service analyzes each report and suggests a category, priority, short summary and responsible department, and detects possible duplicates. Administrators review the AI suggestions, approve incidents and assign response teams, who update progress until the incident is resolved. Everyone is informed through real-time notifications and emails, and administrators monitor everything through a dashboard with charts and reports.
ResQ منصة واحدة، المواطن يبلّغ فيها عن المشكلة بوصف وصور وموقع على الخريطة. الذكاء الاصطناعي يحلل كل بلاغ ويقترح: نوع المشكلة، ودرجة الأهمية، وملخص قصير، والقسم المسؤول، ويكتشف البلاغات المكررة. المدير يراجع اقتراحات الذكاء الاصطناعي، ويوافق على البلاغ، ويرسل فريق. الفريق يحدّث التقدم لين تتصلح المشكلة. والكل يوصله إشعار فوري وإيميل، والمدير يتابع كل شي من لوحة تحكم فيها رسوم بيانية وتقارير.

3. Project Objectives٣. أهداف المشروع

  • Build RESTful Web APIs using ASP.NET Core and C#.
  • Store data in SQL Server using Entity Framework Core.
  • Secure the system with Identity, JWT and role-based authorization.
  • Integrate AI for classification, priority, summary, department and duplicate detection.
  • Integrate interactive maps and an email service.
  • Real-time notifications using SignalR.
  • Incident assignment and tracking workflow.
  • Admin dashboard, analytics and exportable reports.
  • A professional, responsive user interface.
  • نبني APIs بـ ASP.NET Core ولغة C#.
  • نحفظ البيانات في SQL Server عن طريق Entity Framework Core.
  • نحمي النظام بتسجيل الدخول و JWT وصلاحيات حسب الدور.
  • نربط الذكاء الاصطناعي: يصنّف، ويحدد الأهمية، ويلخّص، ويقترح القسم، ويكشف التكرار.
  • نربط خرائط تفاعلية وخدمة إيميل.
  • إشعارات فورية بـ SignalR.
  • مسار كامل لتعيين الفرق ومتابعة البلاغ.
  • لوحة تحكم للمدير فيها إحصائيات وتقارير قابلة للتحميل.
  • واجهة احترافية تشتغل على الجوال والكمبيوتر.

4. Project Scope٤. نطاق المشروع

In scope:
  • Registration and login for 3 roles
  • Incident reporting with photos and map location
  • AI analysis with admin review
  • Response teams and assignments
  • Incident map
  • SignalR and email notifications
  • Dashboard, charts, CSV export
  • Audit logs
Out of scope:
  • Real emergency operations (educational prototype)
  • Native mobile apps, payments
  • Automatic decisions without admin review
داخل المشروع:
  • تسجيل ودخول لـ 3 أدوار
  • إرسال بلاغ مع صور وموقع على الخريطة
  • تحليل بالذكاء الاصطناعي والمدير يراجعه
  • فرق الإصلاح وتعيينها
  • خريطة البلاغات
  • إشعارات فورية وإيميلات
  • لوحة تحكم ورسوم بيانية وتحميل تقرير CSV
  • سجل لكل العمليات المهمة
خارج المشروع:
  • الطوارئ الحقيقية (هذا مشروع تعليمي)
  • تطبيق جوال، أو دفع فلوس
  • قرارات تلقائية بدون مراجعة المدير

5. User Roles٥. الأدوار

  • Citizen: registers, submits incidents with photos and location, tracks progress, receives notifications.
  • Administrator: reviews incidents and AI analysis, approves or rejects, sets priority, assigns teams, manages categories and teams, views dashboard and logs.
  • Response Team: views assigned incidents, updates progress, uploads resolution photos, marks completed.
  • المواطن: يسجّل، ويرسل بلاغ بصور وموقع، ويتابع بلاغه، ويوصله إشعار.
  • المدير: يراجع البلاغات وتحليل الذكاء الاصطناعي، ويوافق أو يرفض، ويحدد الأهمية، ويرسل الفريق، ويدير الأقسام والفرق، ويشوف لوحة التحكم والسجلات.
  • فريق الإصلاح: يشوف المهام اللي تعيّنت له، ويحدّث التقدم، ويرفع صور الإصلاح، ويعلن إن المهمة خلصت.

7. External APIs٧. الخدمات الخارجية

  • AI API (OpenAI / Gemini) – mandatory: classification, priority, summary, department, duplicate similarity.
  • Maps & Geocoding (Leaflet + OpenStreetMap + Nominatim): show incidents on a map, convert addresses to coordinates.
  • Email (Brevo): registration, submission, status, assignment and resolution emails.
All API keys are kept in User Secrets, never on GitHub.
  • الذكاء الاصطناعي (OpenAI أو Gemini) – إلزامي: يصنّف البلاغ، ويحدد أهميته، ويلخصه، ويقترح القسم، ويكشف التكرار.
  • الخرائط (Leaflet + OpenStreetMap + Nominatim): يعرض البلاغات على الخريطة، ويحوّل العنوان لإحداثيات.
  • الإيميل (Brevo): إيميلات التسجيل، واستلام البلاغ، وتغيير الحالة، وتعيين الفريق، وحل المشكلة.
كل المفاتيح السرية تنحفظ في User Secrets، وأبداً ما تنرفع على GitHub.

A working, tested and documented platform showing the full workflow: incident submission → AI analysis → admin review → team assignment → resolution → notifications and analytics.
